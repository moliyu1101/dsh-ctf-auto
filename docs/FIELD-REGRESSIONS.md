# 自动拉题实测问题修复

## 已解状态与候选

平台题的本地校验仍检查 flag 格式与 evidence，但只登记 `localVerified=true`、`verified=false` 的候选。它可以触发自动提交，不会提前把题板置为 `solved`、生成已验证 flag 文件或沉淀已解打法卡。无平台的离线题保留原有本地验证流程。

平台 `correct` 回显或独立 reviewer 明确确认后才升级验证。`already_solved` 表示平台确认题目已经解出，不证明本次提交的候选正确。独立复核通过和平台实际得分仍是两个状态，可分别查看 lifecycle.verification 与 lifecycle.submission。

明确的 `incorrect` / `wrong` / `rejected` 会撤销对应候选的验证及复核标记、记入拒绝事件、同步 flag 文件并清理失效记忆；没有其他可信 flag 时撤销虚假的 `solved`。拒绝记录留在提交流水中，不进入有效 flag 台账和报告的 flag 清单。打包导出的根目录 `flag.json` 始终由已验证台账生成，不读取工作区里可能残留的旧候选文件。相同内层内容的 `CTF{...}`、`flag{...}` 及这些包装的嵌套形式合并为一个候选；最终采用平台确认的完整表示。

## 提交形态与诊断

DASCTF 适配器默认 `flagWrapper="flag"`。通过现有 `platform.config.set` 端点或本地平台配置可指定其他前缀，空字符串关闭归一化；CTFd 和通用平台默认维持原样提交。

一次提交最多尝试三个不重复形态：原样、使用适配器前缀包装去壳内容、去壳内容。仅当上一形态收到明确拒绝且结果已持久化时继续。正确、已解、限流、认证/网络失败、未知回显、租约失效或配置变化都会停止尝试。每个实际发送都有独立的持久化提交边界。平台提交尚未完成时，重试队列等待回显后再派发下一轮，避免重复解题撞车。

事件始终包含非空说明；空说明的 DASCTF 回显保留 code/status/correct 等有限诊断字段，不保存整包响应或认证头。只有传输成功、没有判题结论的响应归为 unknown，不能据此尝试下一个形态。结果未明的提交仍需核对后才允许明确重试，不能因超时而自动重放。

## 环境任务与恢复

- 启动及看门狗恢复会对旧的 unknown start/delete 操作查询平台；同题查询每分钟最多调度一次，全局最多同时四个恢复查询。
- start 观测到 present、delete 观测到 absent 时自动收口。人工接受当前观测仍通过原有主会话/面板操作完成。
- 环境流水收口与对应的无会话 unknown 环境任务在同一事务中更新。旧版本已完成环境流水但未完成任务的记录也会修复，包括远端明确响应已落盘、实例在释放任务前崩溃的情况。
- start/delete 直接返回未知或抛出异常后先自动查询一次；无法确认时继续保留资源保护，后续恢复只查询，不重复创建或删除。
- extend 的完成、观测冲突、凭据不匹配以及带待确认执行会话的任务，不会仅凭资源租约过期自动释放。

## 尝试、工具输出与效率

| 实测项 | 新行为 |
| --- | --- |
| B7 用户停止 | 保留 stopped，明确回执“已按你的停止请求终止，可手动重试”；attempt 标记 stopped-by-user，不自动重试 |
| C8 验证后中止 | 优先按已确认 flag 成功收口；status=completed，验后中断原因记为 verified-stop |
| C9 JSON 输出 | 工具/Web 返回实际 JSON；非有限数值变为 null，对象中移除 undefined，避免操作成功却无法读取结果 |
| C11 无产出 | 默认 5 分钟无事实、事件或 notes/scripts/artifacts 变化时提醒换方向；再过 5 分钟仍无产出则按预算收口重试 |
| D12 重试上下文 | 固定注入候选、拒绝回显、前序事实/失败路径，要求先读 notes.md，优先证伪已有假设 |
| D13 等待估算 | 调度页显示估算等待时间及当前并发占用；旧任务待核对或靶机串行阻塞时显示原因 |

无产出阈值可在设置页修改，或设置 `idleTimeoutMs`，0 为关闭。检测使用单调时钟，不跟随系统日期跳变；工作区扫描有数量/深度上限且不跟随符号链接。提醒本身不算进展。队列估算使用运行中剩余预算及近期尝试时长的中位数；它不保证真实开始时间。

## 升级与验证

重新加载插件即可启用。启动时校正旧的本地“已解”候选、拒绝候选和重复包装；只有验证发生在该次尝试结束前且能确认时间归属时，才修复历史 aborted/timeout 成功摘要，避免把后来人工补交归功于早先失败尝试。原提交回显保留在 journal 中。

回归入口：`npm test`。runner 默认限制为两个测试进程，避免云机大量 HTTP mock 同时启动造成严格超时断言抖动；可用 `CTF_TEST_CONCURRENCY=1..8` 调整并发，断言本身未放宽。`test/security/field-regressions.test.mjs` 覆盖这批实测问题、DASCTF 默认包装、恢复锁、序列化、提示词、时间归属和存储重启；原有测试同步更新到现行持久化、写入锁及单调时钟契约。

验证使用本地 mock 平台与模拟执行端，尚未替代真实 DSH Desktop 面板点按及赛事平台的再次实测。

# 解题预算与单调计时

`budget-timing.js` 负责整题预算的运行时锚点和恢复检查点；编排器负责单次尝试、收尾宽限和停止请求。运行期间使用 `performance.now()`，不再通过系统日期差判断单次超时、整题剩余预算或自动重试资格。日期仍用于事件审计、提示词和预计截止展示。

## 运行期间

- 新题从首次创建尝试前取得的计时样本开始计预算；已开始的题在编排器初始化时建立锚点，等待宿主或会话恢复的时间也计入整题预算。停止、排队期间继续计时，维持原有整题预算语义。
- 单次上限取配置超时与整题剩余预算的较小值。创建记录及派发边界的保存耗时也计入，保存之后再次检查；耗尽时不调用执行端。
- 定时器和看门狗共用运行时单调截止值。定时器提前触发会重新安排；延迟到达的收尾回调不能恢复已过期预算。收尾保存之后再次检查旧截止值，慢保存不能使过期尝试续命；宽限最多使用当时剩余的整题预算。
- 收到执行结果时也核对截止值，避免已完成 Promise 抢先于到期定时器的微任务顺序绕过预算。宿主激活、结果发布和已知 solver 会话的题目工具检查采用同一份运行时剩余时间。无可靠会话身份的旧宿主回退仍有边界，不等于执行隔离。
- 单调时钟报错、非有限读数或回退时，实例保留 `BUDGET_CLOCK_INVALID`，暂停新派发并在计时器或看门狗中请求停止。后续正常读数不自动解封，应修复后重新加载。

`createOrchestrator` 可分别注入 `now` 和 `monotonicNow`。只修改日期时钟不会推进运行时超时；模拟时间的调用方需单独提供单调时钟。未修改或运行现有测试。

## 检查点与重启

每题可保存 `budgetClock: {version:1, epochId, elapsedMs, checkpointAt}`。`epochId` 区分预算周期，即使人工重开时系统日期恰好相同，也不会混淆新旧预算。捕获计时发生在事务外；新周期的运行时锚点只在对应草稿已安装后接纳。事务被拒绝不会更换现有周期。

在创建尝试、人工入队/重试、预算收尾、尝试收口、遗留尝试恢复和关闭活动编排时保存检查点，随对应业务修改一起提交，不额外逐次写盘。它不是每个心跳都刷新的账本。保存失败沿用 dirty 暂停及待收口恢复规则。

重启后使用 `已保存 elapsedMs + max(0, 当前日期 - checkpointAt)` 建立新锚点，此后只用单调增量。日期回退不会扣减已经保存的已用预算；向前的停机时间仍计入预算。没有检查点的旧记录只在初次接入时使用 `max(0, 当前日期 - startedAt)`，之后在正常事务中补检查点。检查点格式或版本不支持时，保留原文件并拒绝加载；事务中写入无效检查点也会被拒绝。

进程间没有可直接延续的单调时钟，停机期间的日期调整和真实停机时长无法在当前架构下可靠区分。突然退出加日期回退时，最后检查点之后的部分时间仍可能漏计；不能宣称跨重启完全不依赖系统日期。不同平台的整机休眠计时语义也可能不同。人工开始/重试仍只在预算耗尽时开启新周期，不自动扩展未决远端任务的执行权限或释放其并发占用。

## 展示与边界

调度快照和题板倒计时采用运行时 `remainingMs`，详情中的当前尝试使用单调 `elapsedMs`，已收口尝试保存耗时供展示和统计。无本地运行时的旧尝试不按预计日期伪造实时倒计时；旧历史记录没有耗时字段时仍可显示原日期差。`deadlineAt` 是预计日期，不能用作授权或远端停止证明。`state.get.budgetTiming` 和调度快照的同名字段提供时钟诊断。

预算到期表示请求停止和阻止新操作，不代表远端执行端已退出。资源释放、未知任务保留及并发名额仍遵守 [任务租约](TASK-LEASES.md) 与 [调度器事务](SCHEDULER-TRANSACTIONS.md)。平台请求、复核、缓存、后台退避等其他计时没有在本轮全面迁移。

仅做语法与差异检查，未运行真实宿主验证；测试、CI 和沙箱继续按当前范围暂缓。

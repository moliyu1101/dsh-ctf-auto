# 平台工作流重构

平台页面使用四个阶段：保存并检查连接、发现与选择题目、准备并入队、解题与平台确认。页面不再将“拉取列表”和“立即开跑”混在一个操作中。

`platform-workflow.js` 负责连接检查、统一题目发现、列表选择快照、自动批次和提交入口；适配器负责协议翻译；导入服务负责输入准备与原驱动会话入队；提交服务负责持久化发送边界、平台回显和未明结果恢复。已有题目、环境、任务及提交流水继续使用原存储，不自动重放旧提交。

## 发现与选择

`platform.challenges` 接收 `sessionId`，返回 `snapshotId`、`expiresAt`、`challenges` 和 `possiblyTruncated`。每道题包含稳定的 `sourceKey` 和当前工作区的 `local` 状态。身份包含连接、练习场/比赛/阶段及题目 ID；同 ID 不同来源保留为不同题目。

服务器保存最多 32 份列表快照，有效期五分钟。快照绑定平台配置代次、发起会话与工作区；配置保存、实例重启、列表过期、会话关闭或目录变化后，旧选择不可使用。返回值不含平台凭据或客户端对象。快照是选择凭据，不是执行授权，导入服务仍在每次异步操作后检查原工作区和连接。

新页面调用：

```json
{
  "snapshotId": "发现接口返回的标识",
  "sourceKeys": ["列表中的完整来源标识"],
  "sessionId": "发起会话",
  "start": true
}
```

向 `platform.import` 提交上述参数。服务器从已保存的列表选择题目，不接受浏览器提供的题面、附件 URL 或平台地址，也不重新拉列表推断用户刚才选择了什么。每批 1–50 题；重复导入由持久化题目来源去重，不重复建题或再次启动已导入题目。失败返回逐题记录；已准备题目保留，可从题目工作台恢复。过期或未知快照只会报错，不自动退回导入全部题目。

旧工具和无快照的 `platform.import` 参数仍兼容。旧式仅按 ID 的选择若对应不同来源会拒绝；全量导入和自动批次仍可按完整来源处理。`pipeline.run` 使用同一个发现入口，支持预览与显式启停；后台自动配置不会覆盖显式 `start:true`。

## 页面行为

前端采用独立平台工作区：左侧平台类型卡片、地址与凭据；右侧题库表格和批次区。题库支持可导入/全部/本地已有/平台已解/已选择筛选、分类筛选和关键词检索；本地每页 20 题，跨页选择保留，最多 50 题。列表区域独立滚动，表头固定；分页不代表额外请求平台远端分页。批次区可逐项移除、清空选择、切换仅导入或准备后开始。结果区展示成功、跳过与失败的逐题回执。高级协议配置折叠显示，深色主题与窄屏布局随宿主变化。

编辑连接配置立即作废当前选择；配置未保存时不能发现题目。保存会检查新连接；切换地址或平台类型且未填写新 Token 时清除原配置中的 Token，DASCTF 仍可使用环境凭据。不会把原平台 Token 隐式用于新地址。

发现题目默认不勾选。用户可搜索、选择当前结果的前 50 项，决定仅导入或准备完成后开始解题。平台已解和本工作区已导入题不可再次选择。结果区显示准备、入队、跳过和失败数量及本地题目 ID；后续解题、提交和核对在单题工作台查看。设置中的后台自动拉题与工具接口保持可用。

## 提交与恢复

局部验证只能产生候选。自动提交仍受复核、任务资源与环境状态约束；发送边界和平台结果先写入持久化流水，再应用到题板。明确 incorrect 标记候选为拒绝；correct 确认 flag；already_solved 只确认平台题目已解，不能确认所提交的候选。网络超时、进程中断或未明结果不自动重复发送，需核对后显式重试。

## 已验证范围与限制

测试覆盖列表与工作区隔离、平台切换、快照选择篡改、重复导入、同 ID 多来源选择、显式入队，以及实际插件 HTTP 路由上的浏览器选择导入。

DASCTF 的 next-challenges 请求扩大为 200 项，达到上限会提示可能不完整；没有已核实的分页协议时不推断下一页。通用平台的字段映射不正确会报错，未实现任意平台分页或附件协议。真实赛事账号、配额与 DSH 模型 provider 仍需实际环境验证；本地测试不会发送真实赛事提交。

## 更多自建平台的接口适配

通用 JSON 模式支持以下三类接入模板，位于前端“高级适配设置”中。载入模板会替换当前适配配置，修改后仍需保存并检查连接。模板是协议配置示例，不表示 GZCTF、NSSCTF 或 CTFHub 已有原生适配。

- 分页列表：自定义页码、每页数量、起始页和抓取上限，合并跨页题目并按 ID 去重。
- 根数组：列表直接返回数组，详情和提交状态位于根节点。
- API Key：使用 `X-API-Key`，并在提交请求体中附带题目 ID。

分页示例：

```json
{
  "listPath": "/api/challenges?game=7",
  "pagination": {
    "pageParam": "page",
    "sizeParam": "limit",
    "pageSize": 50,
    "startPage": 1,
    "maxPages": 20,
    "hasMorePath": "meta.has_more"
  },
  "map": { "list": { "dataPath": "data.items" } }
}
```

`hasMorePath` 可省略，此时不足一页表示结束；配置时必须指向布尔值。重复页或任意一页失败会使整次发现失败，不导入半份列表。达到最大页数则返回已读内容，并标注可能不完整。每页最多 200 项、最多 100 页；不支持游标分页。若服务器忽略分页参数并返回同一页，会报错而不会无限抓取。

鉴权和提交体示例：

```json
{
  "auth": { "header": "X-API-Key", "prefix": "" },
  "submitBody": {
    "challenge_id": "{id}",
    "answer": { "value": "{flag}" },
    "mode": "answer"
  }
}
```

Token 仍在凭据输入框填写，模板中不存放具体 Token。`prefix` 可设为 `Token ` 等平台要求的前缀。提交体仅替换值完全等于 `{id}` 或 `{flag}` 的节点，支持嵌套对象和数组，不执行表达式。未配置 `submitBody` 时继续使用 `submitBodyField`。鉴权请求遇到重定向会报错，请将平台地址设置为最终 API 地址。

# 题目准备与批量移除

宿主创建题目不再先放入执行队列。`challenge-preparation.js` 负责持久化准备阶段，题目记录、目录、附件和派生文件分阶段确认；完成后保持 stopped，由原始请求显式调用开始操作。存储层新增 `removeBatch`，会话移除一次提交全部状态删除，再决定是否清理目录。

创建与重试流程现由 `challenge-inputs.js` 管理，平台导入由 `platform-import.js` 编排；宿主只提供授权、工作区和显式开始动作。这些服务共用附件列表确认及输入上下文检查，模块边界见 [输入服务与宿主边界](INPUT-ARCHITECTURE.md)。

## 创建阶段

| preparation.phase | 含义 | 恢复行为 |
| --- | --- | --- |
| preparing | 已登记意图，目录或附件尚未确认 | 本实例仍准备时等待；重启或失去准备上下文后标记 failed，不自动重读外部文件或下载 |
| files_ready | 附件及其引用已确认，题面/笔记同步待办已保存 | 看门狗或「重试本地同步」恢复文件；确认后转 ready |
| ready | 创建所需题面和笔记已同步 | 保持 stopped，显式开始才进入调度 |
| failed | 附件确认前失败或中断 | 展示原因及题目 ID；显式重试输入准备，保留原记录及文件 |

新建/导入首先持久化 `{version:1, jobId, attemptId, phase:"preparing", createdAt, inputKind}`，本地题同时保存规范化为绝对路径或 URL 的 inputs 列表；同时保存项目工作区，初始状态为 stopped。在成功保存前不创建题目目录，不启动执行端。全局存储目录不再被误认为其父目录对应的项目工作区。

目录叶节点使用独占创建，写入 `.ctf-owner.json`，包含 id 和准备 jobId，再创建子目录、同步文件及目录，保存 directoryOwned。它用于防止错误认领或清理目录，不是授权令牌，也不替代沙箱。归属检查点保存前退出时，只有匹配同一 id/jobId 的有效标记才允许在显式重试中重新确认；标记缺失、损坏或不匹配的已有目录不会被认领或删除。

本地小附件复制到带随机前缀的新路径，同步文件后检查源文件身份、大小和修改时间是否改变。同名附件不会覆盖。缺失或非普通文件明确报错，不再把 missing 条目当作完整输入。`maxFileCopyBytes` 默认 50 MiB，既是单文件复制阈值，也是单次复制总上限；超过单文件阈值仍沿用外部路径引用并标记 external，直接传入的 URL 仍是 URL 引用，未在创建阶段下载。因此 ready 只表示创建协议已完成，不保证外部引用持续有效，更不代表独立执行隔离。

附件写入并同步后，一次事务保存 files、files_ready 阶段、事件及 statement/notes 文件同步待办。题面使用当前状态生成；笔记通过同目录临时文件加独占链接安装，已存在的普通 notes.md 保留，不覆盖用户内容。工作目录需支持同目录硬链接。文件同步成功后将准备阶段标记 ready，并保持 stopped；恢复过程不会重放原来的开始意图。

准备期间若题面文件被另行写入，会停止旧准备过程并保留文件。检查点写盘失败遵守 dirty 暂停，完整内存结果可能仍待保存。失败响应保留关联 id、code 和 applied；用户应先查看这条记录，而不是反复创建新副本。

## 平台导入

平台导入在排队前固定连接、工作区及请求参数快照，每次异步结果返回后复核连接代次、发起会话工作区、准备批次和目录归属。平台查询失败不再退化为只凭列表数据创建可执行题目；详情和列表均没有可确认的附件列表时继续查询，仍缺失则报错。任一附件下载失败、格式无效或超过上限，本题不转为 ready；不会默默缺少附件仍开始解题。

单题最多下载 10 项、每项 20 MiB、总计 50 MiB，文件以独占新路径写入并同步。所有附件完成后再确认 files_ready，然后复用文件投影恢复。输入准备期间，生命周期、解题编排和任务登记都阻止执行；后台恢复也不会先派发。初次导入失败的记录参与平台题目去重，可直接在原记录上重试输入准备。

批量结果保留已完成题目及逐题错误、关联 localId；创建成功但启动失败也会报告。跑板报告实际导入数量，部分失败不再被写成零导入或全部成功。中途切换连接或关闭实例时，旧请求返回后不再继续写附件。平台只读查询没有跨远端事务，也没有跨进程下载接管。

## 显式重试输入准备

面板「重试输入准备」和主会话工具 `ctf_challenge_prepare({id})` 共用 `challenge.prepare` 应用命令。仅 stopped、failed 或无本实例活动句柄的 preparing 记录可恢复；已有附件引用、尝试、flag、未决任务、资源占用或本地同步待办时拒绝。生命周期返回 `permissions.prepare`，解题子代理无权调用。

重试保留题目 ID、目录和创建 jobId，先持久化新的 attemptId，再读取外部输入。进程内活动句柄按 attemptId 管理；每次异步返回复核批次、状态、题目来源、工作区、平台连接代次和输入字段。旧请求不能完成、标记失败或释放新批次。准备期间另行修改题面或附件引用也会拒绝旧结果。重试完成仍保持 stopped，不恢复历史开始意图。

本地输入默认重新读取保存的 inputs；主会话可用 `ctf_challenge_prepare({id, files:["/absolute/input.zip"]})` 显式替换本地来源，确认无附件时传 `files:[]`。旧本地记录没有 inputs 时必须提供该参数，不能把未知列表默认为空。旧记录带平台元数据时按平台输入恢复；新记录通过 inputKind 区分手工创建与平台导入。

平台输入只从当前配置与原来源一致的连接重新查询详情，重新获取全部附件地址并下载。缺少详情附件列表时重新查询列表；仍不能确认则拒绝，不能默认为无附件。题目编号不匹配也拒绝。完整下载后一次提交最新题面、目标及附件引用；下载过程与首次导入共用 platform-inputs.js。不会根据文件名、旧签名 URL 或本地文件存在来推定下载完成。

已有 notes.md、scripts、artifacts 保留。旧的部分附件留在 files 中供核实，重试写入独占新文件；未实现分块续传、附件去重或旧部分文件自动清理，因此反复失败会占用额外磁盘。已确认归属的目录或 files 子目录丢失时要求先核实恢复，不能悄悄换目录；已有 statement.md 会被保留并报错。

files_ready 不重新下载，请使用「重试本地同步」或 `ctf_challenge_sync({id})` 完成派生文件同步。preparing/failed 阶段调用同步工具会明确返回 CHALLENGE_NOT_READY，不再把没有同步待办误报为输入就绪。所有恢复仍遵守 dirty 暂停。

## 移除顺序

`store.removeBatch([{id, expectedRevision}], {durable:true})` 最多处理 128 个不同 id，先核对全部存在性与修订；任一失败均不删除记录。校验成功后一次修改题目映射和 order，共享一次同步保存。保存失败返回 `ok:false, applied:true` 和完整 ids，表示删除已应用到内存但仍待保存，所有目录保留。

会话移除在调用前检查全部题目的工作区及生命周期。仍在准备、使用、有任务、投影或平台结果待核对的任一题目会阻止整批移除。超过 128 个时明确拒绝，不拆批造成部分删除。单题移除也走同一保存路径。

只有状态删除保存成功且显式设置 deleteFiles，才尝试清理文件。目录必须是配置根目录或 `.ctf-auto` 下、名称匹配 slug 的直接子目录，不能是根目录自身或目录链接。新题还要求 directoryOwned 及匹配的归属标记；没有确认创建的现存目录一律保留。仍被其他保留题目或附件路径引用的目录也保留。

文件清理失败不会撤销已完成的题板移除，响应和界面显示目录保留说明。清理不是持久化队列：删除状态保存失败或进程在提交后退出时，不会在后台继续删除目录。被保留的目录及准备中断留下的文件需按返回信息核实处理。

## 兼容和边界

状态格式升级为 **v4**，继续读取 v1/v2/v3；旧程序会拒绝 v4，避免忽略准备阶段或 notes 同步待办后派发。旧记录没有 preparation 时沿用原有就绪语义，不伪称旧附件已经重新检查。底层 addChallenge 保留无准备记录的兼容调用方式，宿主所有创建入口则通过准备服务。

这不是跨文件原子事务，也没有自动回滚已产生的文件。清理检查不能消除其他进程在检查后替换路径的竞态，不能作为执行沙箱。I/O 仍有同步操作，Windows 不 fsync 目录，实际宿主及文件系统行为尚未运行验证。

仅做语法与差异检查，未新增或运行测试、未修改 CI，沙箱继续暂缓。

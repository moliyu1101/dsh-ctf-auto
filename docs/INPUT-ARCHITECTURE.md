# 输入服务与宿主边界

题目创建、平台导入和失败准备恢复已从 `index.js` 的业务流程中拆出。工具名、Web 端点和状态格式 v4 保持兼容，题目仍通过准备阶段后才能显式启动。

## 职责

| 模块 | 职责 |
| --- | --- |
| `index.js` | 装配服务、会话与工作区授权、选择题目目录和驱动会话、执行显式开始；仍负责跑板策略、其他工具与面板业务 |
| `input-context.js` | 捕获工作区/目录/驱动标识及同步授权检查函数，拒绝缺失或异步的检查；提供关闭与持久化屏障 |
| `challenge-inputs.js` | 本地附件来源校验与复制、题目创建流程、原记录准备重试、资源与来源复核 |
| `platform-import.js` | 导入排队、请求快照、来源去重、逐题准备、部分成功汇总、显式开始回调 |
| `platform-inputs.js` | 平台题面转换、附件列表确认、限量下载与独占文件写入 |
| `challenge-preparation.js` | 持久化准备阶段、目录归属、准备批次身份及迟到结果保护 |
| `challenge-projections.js` | 题面/笔记等本地文件同步与 files_ready → ready 收口 |

服务只依赖注入的状态库、连接、准备阶段、资源与生命周期接口，不持有 DSH ctx、Agent 或面板请求。宿主把实际会话权限放在同步检查函数中；服务不能仅凭调用方提供的 workspace 字符串判断授权。缺少可信检查函数返回 INPUT_SCOPE_REQUIRED，检查返回 Promise 则返回 ASYNC_INPUT_SCOPE，不能跳过授权继续执行。

## 排队与异步边界

平台导入在入队前复制 ids、all、skipSolved、start 和已选择的列表数据。工作区、目录、驱动标识和授权函数引用同时固定；队列执行时不重读原始 payload。请求调用方后续修改数组或属性不会改变已排队请求。连接在入队前选定，执行及每次异步返回重新核对当前连接代次。

同连接、同工作区的导入继续串行。每次详情返回后重新检查去重索引；索引按当前导入工作区和 store.changeVersion 构建，状态发生变化即失效，不跨工作区共享，不长期缓存远端列表。字段校验和来源 ID 校验保留。

首次导入与准备重试共用附件列表确认逻辑：优先采用详情中的列表，首次导入可采用已获取列表中该题的附件字段；均缺失时重新查询相同来源的题目列表。仍缺失则返回 ATTACHMENT_MANIFEST_MISSING，不能把未知列表当成空数组。适配器返回的空数组表示该适配器确认无附件，仍依赖适配器的数据转换契约。

写附件前后检查授权、实例存活、连接和准备批次；准备服务负责身份与磁盘一致性检查，同一次准备检查不额外重复读取整份状态文件。复制与下载仍有同步文件 I/O，本次没有改为流式传输或增量存储。

## 收口与关闭

准备完成后保持 stopped。仅原始导入请求的 start=true 才调用宿主提供的开始函数；默认不自动执行。驱动会话在入队前固定，缺失或工作区变化时报告启动错误，已准备题目仍计入 created，之后可在正确会话中显式开始。

关闭实例时先关闭导入与输入服务，再关闭准备、投影、平台连接和状态库。排队及晚返回的输入操作均检查关闭状态。授权、连接或磁盘失效发生在批量处理中时，返回已创建题目与逐题错误后停止，不能丢失前面已经完成的进度。逐题导入事件及驱动标识同步持久化；保存失败遵守 applied/dirty 语义，不再次下载覆盖已确认输入。

本次没有持久化网络队列、跨文件事务或独立执行沙箱。准备中断后的再次下载仍需显式触发；分块续传、部分文件自动清理、真实宿主与平台联调继续待办。仅做语法及差异检查，未新增或运行测试，未修改 CI。

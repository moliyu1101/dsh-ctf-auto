# 状态快照与题目事务

## 解决的问题

此前 `addFlag`、`setStatus`、`removeFlag` 会在修改内容和追加事件时分别保存；宿主的 flag 登记又会连续保存 flag、事实、降级说明和结束时间。进程中断时可能留下缺少关联字段的中间状态，也会重复序列化整个状态库。`get()` 返回内部对象，调用方还能直接改写字段。

现在将不涉及 I/O 的编辑规则集中到 `challenge-editor.js`，旧单题写接口和新事务入口共用事务与编辑规则，保留去重、上限、验证证据强度和状态事件行为。兼容接口的单次修改最多保存一次，无改动不写盘。

## 接口与边界

`store.read(id)` 返回 `{revision, challenge}`。`challenge` 是递归冻结的独立副本，修改不会影响库内对象。`revision` 为当前题目 JSON 内容的 SHA-256 摘要，不是递增序号，也不是授权凭据。

公共 `get/list/findBySlug/state` 和创建结果现也只返回冻结快照；单题缓存按实际安装的修改失效。实体身份改用私有快照关联的 `store.owns()` 判断，普通更新不使身份失效，但旧内容不会自动刷新。接口迁移与业务恢复规则见 [只读状态接口与实体身份](READ-ONLY-STATE.md)。

`store.metadata()` 返回递归冻结的根元数据副本，包含 version、updatedAt、rootDir、order、running、stats，不包含可变题目对象。宿主搜索和报告已使用这个入口，移除了直接写入 `store.state.rootDir` 的路径；根目录由存储构造参数和加载流程管理。

`store.transact(id, operation, options)` 在独立草稿上同步执行编辑，验证后一次提交并保存。回调获得 `(edit, draft)`，编辑器支持字段、flag、事实、事件、状态，以及 `addAttempt`、`updateAttempt`、`endAttempt`。传入 `expectedRevision` 可拒绝基于旧内容的修改，`durable:true` 使用关键阶段的同步保存。

```js
const snapshot = store.read(id);
const result = store.transact(id, (edit, draft) => {
    const flag = edit.addFlag({ value, verified: false, method: "manual" });
    if (!flag) return { ok: false, error: "候选已达上限" };
    edit.addFact({ text: `记录候选：${flag.value}` });
    edit.addEvent("note", "候选和事实已一起登记");
    return { flag: flag.value };
}, { expectedRevision: snapshot.revision });
```

事务具备以下约束：

- 回调抛出异常或返回 `{ok:false}` 时丢弃草稿，不安装到当前题目。
- 返回 Promise 的回调不能提交。异步延续只持有草稿，草稿不会被直接安装成库内对象；回调仍必须遵守不执行 I/O 的契约。
- 提交前检查题目标识、状态和关键数组结构，检查序列化能力，并再次核对内容修订与题目对象是否仍匹配。
- 提交复制修改后的字段，内部保留实体身份，公共读取不再暴露根对象。提交/环境服务分别检查实体身份与来源归属，并重新读取最新字段，不依赖公共对象引用相等或旧字段自动更新。
- 无改动不写盘。正常修改只保存一次；保存失败返回 `ok:false, applied:true, code:STATE_NOT_DURABLE`，内存保留完整业务修改并标记 dirty，等待现有恢复保存机制处理。
- 进入事务前若已有 dirty 状态，则拒绝新事务。恢复持久化后再推进业务，避免叠加未保存的操作。

内容摘要检查读取与提交之间的内容变化，但不能检测内容先变化又恢复的 ABA，也不提供跨进程比较并交换。revision 包含全题的事件和输出变化；长时间运行的工作应在返回后重新读取，并先判断与业务相关的候选、来源或目标是否仍适用，不能盲目用很早的整题 revision 阻塞所有后台更新。

状态库另有实例级独占锁和磁盘文件摘要校验。`createStore()` 在加载前取得所有权，第二个实例不能并行加载同一状态文件；`checkWritable()`、事务和旧写接口检测锁失效或磁盘内容冲突。调用方使用结束后必须 `close()`。这是写者准入保护，与上面的单题 revision 分开，详见 [存储写入所有权与磁盘冲突](STORAGE-OWNERSHIP.md)。

`transactBatch()` 现可将至多 128 道已有题目的同步草稿合为一次保存：全部校验成功后才安装，失败不提交其中一部分。`transact()` 共用该实现，默认仍返回只读快照；任务后台写入可关闭完整快照，周期维护已使用多题批量保存。准备阶段禁止嵌套事务、save、close 和旧写接口。接口和边界见 [批量事务与任务维护保存](BATCH-PERSISTENCE.md)。

## 已迁移的业务

| 操作 | 一次事务中的内容 | 事务外的效果 |
| --- | --- | --- |
| flag 登记 | 候选/验证信息、事件、事实、降级说明、无运行尝试时的结束时间 | flag.json、打断子代理、触发自动提交 |
| 候选移除 | 移除候选及事件、无剩余验证 flag 时的 stuck 状态 | 无 |
| 复核结果 | 复核记录、匹配候选的降级、题目状态、复核事件和事实 | 更新记忆文件、修正 flag.json |
| 提交流水 | 阶段/结果、兼容投影、该次提交的事件 | 请求平台、登记本地证明与文件 |
| 调度器尝试 | 创建与收口、预算、指标、候选、事实及状态决策 | 召回、派发、中断、使用计数 |
| 自动分类 | 分类、分类来源/依据、关联事件和驱动会话元数据 | 启动编排 |
| 靶机探测 | 目标仍匹配时的探测状态及变化事件 | 探测网络请求 |
| 平台提示 | 同次返回的提示事实和解锁事件 | 平台查询和解锁 |
| 平台刷新 | 题面、附件引用、分类/目标、靶机标记、事件、题面文件同步待办 | 平台查询/下载、新路径附件安装、投影写出 statement.md |

靶机探测先捕获只读目标，异步返回后在草稿中核对地址，旧地址结果不再覆盖新目标；保存失败返回明确错误。提示登记按捕获的平台连接与当前工作区选本地题目，存在多个同编号候选时不任意选择；写入时再次核对题目来源。远端解锁与本地记录没有跨系统事务，本地保存失败时响应保留已收到的 unlocked 回显，不应盲目重复解锁。

## 兼容单题写接口

`update`、`addAttempt`、`endAttempt`、`updateAttempt`、`addFlag`、`removeFlag`、`addFact`、`addEvent` 和 `setStatus` 已统一调用 `transact`。草稿校验、dirty 拒绝、嵌套写入保护和磁盘冲突检查与新入口一致。返回对象是递归冻结的独立值，不能再修改返回的 attempt/flag/patch 来改变库内对象。无题目时仍返回 undefined，removeFlag 仍返回 false。

兼容调用方没有结构化事务返回值，所以失败会抛出带 code、applied、persistence 的错误。`applied:true` 表示完整修改已经安装到内存但写盘失败，不能当作已经回滚；恢复保存前拒绝后续修改。宿主使用多条兼容调用完成的业务仍不自动合成一个事务，应逐条迁移为显式业务事务。

创建使用受保护的登记路径，宿主额外记录 preparing/files_ready/ready/failed 阶段，输入确认前保持停止。删除现提供 removeBatch，全部校验后一次保存多题移除；会话移除和单题移除均接入，成功后才尝试清理目录。这些路径在 dirty 时拒绝修改，保存失败明确返回或抛出 applied:true；文件与状态之间仍不是原子事务。见 [题目准备与批量移除](CREATION-REMOVAL.md)。

停止通知先发给执行端，再尽力写审计事件。审计保存失败会记录诊断，不阻止中断，也不把已经观察到的执行结束改成远端未知；未安装的审计内容没有额外持久化待办，不承诺恢复。

题目应用服务的读取和单题详情使用只读快照；详情还返回 revision。事务错误经宿主转换后只返回错误和持久化信息，内部题目快照及凭据配置摘要不会附在错误响应中。

提交流水在关键保存失败后可能留下完整但未保存的内存阶段。恢复循环会在该题已无活动或排队提交时，将 prepared 收口为未发送，将 sending 收口为 unknown；不会因为仍有活动操作而提前收口，也不会自动重放远程提交。

## 尚未迁移的部分

公共读接口和创建结果已收敛为冻结快照，原单题写接口也经过事务；创建输入已分阶段确认，批量删除已一次提交。宿主其他多步提交、创建前半段附件中断的续接及删除后文件清理的持久化恢复仍待完善，它们尚未组成跨文件原子工作流。

事务覆盖同一进程、同一状态文件中选定题目的 JSON 状态。文件、记忆库、网络和子代理生命周期不在事务内，保存失败也不回滚已经发生的外部副作用。flag 和复核拒绝后的文件同步现已通过持久化待办恢复，见 [学习数据保护与本地文件恢复](LEARNING-PERSISTENCE.md)；它不是跨文件原子事务。

上层现已提供持久化任务身份、协调端心跳与统一取消请求，见 [统一任务登记、租约与取消](TASK-LEASES.md)。状态格式写入 v4，继续读取 v1/v2/v3；旧程序会拒绝高版本状态，避免忽略任务租约或输入准备待办后派发。后续仍需远端 fencing token、跨独立状态目录协调、更通用的创建/更新/删除多实体事务、增量持久化及独立读模型。内容摘要和草稿复制仍有成本，不宣称已完成大型题板的性能优化。

按当前范围，本轮未新增或运行测试，未修改 CI；仅检查语法和差异格式。沙箱继续暂缓。

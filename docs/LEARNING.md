# 记忆与知识库升级

本轮在实验黑板、依赖证据和独立复验的基础上，升级可复用记忆与资料检索。全部本地运行，没有增加 embedding 服务、外部数据库或额外模型调用。

## 记忆：保存可核验的方法和适用范围

题目仍须满足原来的 flag、平台提交、独立复核和资源收口条件才能沉淀；当前材料范围内存在未决实验争议时暂停沉淀。

有结构化实验时，从文件摘要匹配、前置条件有效的 supported 记录提取步骤、命令和识别特征，最多十二项。猜测和已证伪路径不混入成功步骤。最多保存八项 refuted 记录作为**带明确测试范围的负结果**；重试其他题时必须核对条件，不能把旧范围的失败当成普遍结论。引用证据失效、无法核验任何已声明的成功路径时，拒绝退回成只靠笔记的卡片。

没有结构化成功步骤的旧题，仍可在最终得分已核验时沉淀，但会明确标为“最终结果核验通过，笔记步骤仅供参考”。命令抽取不等于命令正确，任何卡片都不能替代本题复现。记忆正文中已登记的历史 flag 原文会被替换，继续保留来源路径与文件摘要供核对。

每张新卡保存：

- 题目材料、核验结果与实验版本的来源身份摘要；
- notes 和 Writeup 的文件摘要，包括“当时文件不存在”的状态；
- 成功步骤、负结果以及各自的实验版本、证据和前置快照；
- 覆盖配方内容和来源的版本摘要，用于发现配方被改写、绑定召回记录和效果反馈。

召回前重新核对来源台账、文件字节与实验引用。来源变更、争议、文件损坏、旧卡缺少快照，或该版本有矛盾反馈时，暂停自动召回，并在面板列明原因。暂停不是删除；原有 flag 复核拒绝触发的撤销清理流程仍然执行。

卡片不能通过自己保存的任意根目录请求宿主读文件：核对路径须匹配当前题目目录与配置的 Writeup 目录。文件读取有大小上限，并拒绝符号链接、非普通文件和读取期间的替换。

## 知识库：段落匹配与可定位引用

以 Markdown 标题和行号构造重叠片段，使用 BM25 词频、语料稀有度、长度归一化和标题权重召回。保留中文二元词与英文标识符；相同题型或历史“成功次数”不能单独产生无关键词命中的结果。显式 `ctf_kb_search` 默认仍保留 AND 查询语义，自动召回使用部分匹配并返回匹配词和依据。

每项结果包含资料 id、文件内容 SHA-256、片段摘要、起止行号、片段版本和来源属性。同一段落的重复文件合并展示；每份文档仅选最相关的一段，避免同一长文占满上下文。知识内容是参考资料，不是操作指令；文件摘要只能定位字节，不能证明作者说法正确。

来源规则：

| 来源 | 自动召回 | 手动检索 |
| --- | --- | --- |
| 原始 notes | 不自动注入；可复用步骤交给证据记忆 | 保留，并标明原始笔记 |
| 能对应到台账的 Writeup | 来源仍满足核验条件且无争议时可参考 | 保留来源状态 |
| 无台账关联的历史 Writeup、导入资料 | 作为外部参考，未经内容验证 | 可用 |
| 有矛盾反馈的片段版本 | 暂停 | 可查看反馈标记 |

自动召回排除当前题目自己的资料。每次检索重新核对文件内容，修改、删除不会继续命中旧的十五秒缓存。`kb.stats` 与 `kb.search` 返回扫描诊断，跳过不可读取或超限的来源不会伪装成完整索引。

当前限额：单文件 2MiB，每次最多 500 个文件、32MiB 文本；每文档最多 128 个片段，单次检索最多评估 4096 个片段。大规模资料宜拆分，分批导入；不保证覆盖超限部分。自动知识与记忆上下文各自限制在约 6000 字符以内。

## 效果反馈：区分召回、共同出现与实际判断

保留旧 `used/usedOk` 计数用于兼容，界面改称“召回次数/召回后解出”。这是共同出现的观察，不能证明每条资料都有用，因此不再据此增加召回排序分数。现有 `confidence` 字段是启发式质量分，也不是成功概率。

启动尝试时，只记录实际进入有限提示词上下文的资料版本；知识还记录当时的行号和文件摘要。因预算省略的候选不计入该快照。读取库失败会留下降级提示，不静默当作没有相似经验。

在题目详情「历史资料的实测反馈」，主会话可选择该次尝试的资料，填写判断、实测依据和本题证据路径。也可以调用：

```json
{
  "id": "本次题目 id",
  "attempt": 1,
  "kind": "memory",
  "referenceId": "attempt.memories 中的 id",
  "revisionId": "该条快照的 revisionId",
  "verdict": "helpful",
  "reason": "说明实际执行过程、输出，以及该资料提供了什么帮助，至少十二字符",
  "evidencePaths": ["artifacts/replay.txt"]
}
```

以上参数传给 `ctf_learning_feedback`。`kind` 为 memory 或 knowledge；`verdict` 为 helpful、inapplicable 或 contradicted。必须引用本题内已保存的实测文件，不能给未进入该次尝试快照的资料版本补记效果。当前不追补后续手动搜索的召回统计。

同一尝试、资料与版本只有一项当前判断。完全相同的重试去重；修改反馈须带返回的 `expectedVersion`，保留最多四个历史版本。helpful 只给匹配项小幅加权；inapplicable 表示这次条件不适用，不全局封禁方法；contradicted 暂停该版本自动召回，等待显式复核、更正资料或反馈。知识反馈按片段内容和标题范围绑定，复制或改名同一段落不能绕过矛盾记录；新的不同内容不自动继承旧版效果。

反馈保存的是记录时的人工判断和文件摘要，不是自动证明的因果关系；再次作判断仍需复验。解出题目不会自动生成 helpful。解题子代理和辅助代理不能自评加权，反馈仅允许主会话或有题目权限的面板操作。此机制不改变 flag 或比赛得分。

反馈写入 `learning-feedback.json`，独立原子保存、带版本冲突检查。存储失败可重试，不重复计数；最多 2000 项，不覆盖旧证据。损坏或未知版本的记忆、反馈保留原文件并报错。

## 旧数据与迁移

现有 v1/v2 卡片和使用统计保留，新卡继续使用 v2 外层格式，并增加带独立 schema 的证据元数据。缺少来源快照的旧卡暂停自动使用，面板会显示原因。来源仍在台账且满足核验条件时，点击「重新核验并重建」，或指定题目执行 `memory.distill`。

批量重建只处理缺失或已失效的卡，每批最多五十张，返回 `remaining`；后续批次会继续处理剩余旧卡，不会反复覆盖已经更新的前五十张。新题首次批量沉淀每批最多二十张。来源不存在、争议未决或证据损坏时须先修复；不会凭空给旧卡补上“已验证”。

## 验证边界

自动化覆盖检索排序、长文引用、重复合并、来源新鲜度、失败路径隔离、历史 flag 正文移除、旧卡迁移、上下文预算与实际引用快照、反馈权限、版本冲突和写盘失败重试。真实 DSH 面板交接、较大资料库的交互性能以及比赛解题率变化仍需实测，没有用单元测试结果宣称解题效果提升。

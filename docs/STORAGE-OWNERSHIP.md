# 存储写入所有权与磁盘冲突

## 状态库只允许一个实例写入

`createStore()` 在加载 `state.json`、备份损坏文件或创建空状态之前，使用 `file-lock.js` 独占创建同目录的 `state.json.lock`。该锁一直持有到 `store.close()`，不是仅覆盖一次保存的短锁。第二个实例拿不到锁就以 `FILE_LOCKED` 终止初始化，不读取旧状态后启动第二套调度。

锁使用 Node 内置文件 API：`open("wx")` 独占创建，文件权限为 0600；元数据包含版本、随机标识、PID、主机名和创建时间，不含平台凭据。现有目录的符号链接先解析到真实目录，使指向同一目录的常见路径别名使用同一把锁。状态文件本身若是符号链接或非普通文件，拒绝加载和保存，不重建覆盖。

持有期间保留打开的文件描述符，并以设备号与 inode 检查锁仍属于当前实例。锁被删除或替换后，保存返回 `FILE_LOCK_LOST`；旧实例不会删除后来出现的锁。正常释放只删除自己仍持有的锁文件，不递归删除目录、不清理其他实例的临时文件。

## 磁盘内容保护

状态库记录上次成功加载或安装的文件内容摘要。事务与旧写接口在修改前检查写入所有权及磁盘摘要；保存在创建临时文件之前、安装目标文件之前再检查一次。发现外部改写或删除时返回 `STATE_DISK_CONFLICT`，保留外部内容和当前内存中的未保存状态，不自动用内存旧副本覆盖文件。

新文件以同目录硬链接独占安装，已有文件继续以 rename 替换。安装后立即更新已知磁盘摘要；随后 fsync 失败仍可以重试同步，不会把本实例已安装的文件误判成外部冲突。关键保存的同步要求会随 dirty 重试保留。

`checkWritable()` 返回结构化检查结果；`persistenceStatus()` 增加 `closed`、`lockPath`，并在 `lastError` 中保留具体错误消息。题板展示实际错误。磁盘冲突和锁失效会阻止后续修改及后台循环；只读查看仍可用于检查当前内存状态。

## 学习文件使用短写锁

`json-repository.js` 每次 commit 都先取得对应 `<文件名>.lock`，再核对调用方的预期内容摘要、写临时文件、检查所有权、安装并同步文件，最后释放锁。因此不同状态目录共享记忆库时，遵守协议的写者不会同时落入“检查后替换”的窗口。

读取及草稿准备可以在锁外执行。如果其他写者已经保存，取得锁后返回 `JSON_CONFLICT`，不把旧草稿合并覆盖到新文件；调用方下次重新读取并重试。锁正在被占用时直接返回 `FILE_LOCKED`，不阻塞 Node 线程等待。使用统计和文件恢复待办会按既有退避机制重试。

计数与回执仍在同一个目标 JSON 文件中保存。短锁只保护文件写入，不把多个状态目录变成同一套任务队列，也不提供跨文件事务。

## 关闭和异常恢复

宿主加载后续步骤失败时会关闭已创建的状态库。正常卸载先关闭业务服务和编排器，再在 finally 中调用 `store.close()`；即使其他清理步骤抛错，也会尝试关闭状态库。已关闭实例的迟到激活及写接口会被拒绝。直接使用存储模块的调用方必须显式调用 `close()` 才能在同一进程中重新打开同一个状态文件。

关闭会尝试同步已有 dirty 状态，返回失败时宿主记录具体错误，再释放所有权；不会为了解锁而覆盖外部冲突文件。关闭失败不会在再次 close 时伪报成功。正常进程退出也尽力释放仍持有的锁。

**异常终止可能留下锁文件。** 不按文件年龄、PID 探测或过期时间自动删锁：暂停、PID 重用、容器命名空间和共享目录都可能让这种判断误删活跃实例的锁。元数据只是排查线索，不是持有者已退出的证明。

遇到残留锁时，先停止使用同一状态文件的实例；共享学习文件还需停止使用它的其他实例。备份数据，确认没有写入者后，仅删除报错指出的 `.lock` 文件，再加载插件。不要删除 `state.json`、记忆库、统计文件或仍被使用的锁。元数据为空、损坏或不可读时同样保留锁并报错，不猜测它已失效。插件热重载也应先卸载旧实例，再加载新实例。

## 边界

- 这是遵守协议的本地文件写者互斥，不是远程任务租约、心跳或平台 fencing token。旧子代理是否已停止仍依赖宿主；独立沙箱仍暂缓。
- 人工编辑、旧版本程序及绕过锁协议的写者不受排他保护。摘要能发现大部分外部修改，但不是操作系统级比较并交换；最终检查与 rename 之间仍可能被不遵守协议的写者插入。
- 不支持把硬链接文件别名当成不同状态库，也不承诺跨机器或具有不同文件语义的网络文件系统、异常设备上的锁和断电一致性。
- 未引入 SQLite、增量日志、自动失活接管或独立读模型。摘要检查增加同步读盘开销，当前仍按全量 JSON 保存；大型题板性能需后续调整。
- 本轮仅做语法和差异检查，按当前范围未新增或运行测试、未修改 CI，实际宿主热重载和跨平台文件行为尚未验证。

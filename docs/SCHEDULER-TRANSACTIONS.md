# 调度器事务与尝试身份

## 调整范围

调度器不再通过 `store.get()` 获取可变对象后直接修改尝试。它使用 `read()` 取得快照，以 `transact()` 提交单题修改；`store.list()` 只用于筛选和计数。尝试编辑规则放入 `challenge-editor.js`，预算及收口决策放入纯模块 `attempt-lifecycle.js`。

| 边界 | 同一次保存的内容 |
| --- | --- |
| 开始/人工重试入队 | 预算扩展或时间起点重置、queued 状态、提示事件 |
| 创建尝试 | 尝试编号和 runId、running 状态、角度、角色、技能、召回引用、提示词字符数、超时及截止时间、开始事件 |
| 结束尝试 | 输出候选、输出尾部、字符/Token/费用估计、失败路径、事实、结束事件、最终状态或自动重试决策 |
| 预算收尾 | wrapupAt、deadlineAt、收尾事件 |
| 中断恢复 | 遗留尝试的 aborted 状态与 finalizedAt、恢复事件、重新入队或 stuck 决策 |
| 子代理绑定 | 当前尝试匹配后保存 sessionId |

召回、读取角色卡发生在创建事务前，派发和中断发生在事务外。事务中准备提示词并保存其字符数，创建事务保存成功后才调用派发端口。

## 运行标识与迟到结果

新尝试生成 UUID `runId`，并使用递增编号 `n`。编辑器不允许通过普通 `updateAttempt` 修改编号或运行标识。

收口必须匹配当前最后一次尝试的编号及 runId。`finalizedAt` 标记已经收口，保存重试不会重复追加候选、事实和结束事件，也不会覆盖用户随后修改的状态。旧数据可不含新增字段，重启恢复仍能处理遗留尝试。

宿主在激活前、激活返回后及结果返回后检查尝试身份。绑定 sessionId 也在事务中复核身份；绑定失败或激活已过期时请求中断子代理。已知历史 solver 会话若不再属于当前运行尝试，其题目工具调用返回 `STALE_ATTEMPT`，不会通过 cwd 回退绕过这项检查。

这些检查只保护本插件管理的尝试、绑定及工具入口，不等同于独立沙箱，也没有撤销宿主原生文件或 shell 工具权限。没有可靠会话身份的旧宿主回退路径尚未全面迁移为资源租约。

## 保存失败与调度暂停

状态 dirty 时不派发新尝试。创建意图保存失败时不会启动子代理；若完整创建结果已在内存应用，则保留对应收口计划，等持久化恢复后收口这次未成功派发的尝试。

尝试执行完毕但收口无法保存时，保存一份有界结果计划：输出尾部最多 4000 字符，候选最多 100 条，并保留输出字符数等指标。该题在计划处理前不会重新派发。停止请求仍先发出中断；停止状态保存失败时保留停止意图，避免磁盘恢复后立刻重新运行。

看门狗先重试停止及完成计划，再收口失去运行句柄的遗留尝试，随后恢复已经启用的调度。启动阶段仍等待宿主可用会话，由宿主恢复入口显式开启队列。

非持久化原因导致的创建错误会出现在调度快照 `preparationErrors` 中，阻止同一条坏记录在微任务中无限重试；显式开始/重试或成功恢复可以清除阻塞。快照同时返回 `pendingCompletions`、`pendingStops`。

这些待处理计划只在内存中保留。如果磁盘持续不可写且进程退出，尚未保存的输出和停止意图仍可能丢失；下次启动按最后成功保存的状态恢复。不能据此宣称已实现持久化任务队列。

## 截止时间和停止顺序

普通定时器、看门狗和详情中的截止时间使用同一个 `deadlineAt`。进入预算收尾后按实际收尾时间加宽限期计算，避免看门狗仍按原截止时间提前中断。零宽限配置现在保留为零。

人工重试后再点击停止，以最后的停止意图为准，不会因旧的 retryRequested 将题目重新入队。普通开始不再越过已用尽的尝试预算；人工重试仍按原规则有限扩展预算。

插件卸载调用 `close()`，而不是仅停止当前任务：关闭调度、收口仍在运行的尝试、清理定时器，并拒绝旧调度器的后续提交。宿主派发回调也检查卸载标记。关闭时若无法保存，依旧受前述持久化限制约束。

## 当前边界

- 此轮没有统一 solver、review、提交、环境清理之间的资源占用；清理排队后的资格复核和环境操作流水仍待实现。
- 使用记录的记忆/知识计数在收口保存成功后按进程内最佳努力更新；它们属于其他文件，没有跨文件事务或恰好一次保证。
- 历史 store 写接口及宿主其他模块仍保留，尚未完成整个项目的强制只读存储改造。
- 只做静态语法和差异检查，未新增或运行测试，未修改 CI。沙箱改造继续暂缓。

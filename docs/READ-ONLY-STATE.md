# 只读状态接口与实体身份

状态库的公共读取入口不再返回可变内部对象。内部题目只由事务、受保护的创建/删除和加载流程维护；业务拿到的是递归冻结的 JSON 数据快照。只读接口本身不需要磁盘迁移，当前格式 v4 的准备阶段见 [题目准备与批量移除](CREATION-REMOVAL.md)。

## 读取接口

| 接口 | 结果 |
| --- | --- |
| `get(id)` | 当前题目的冻结快照，不存在时 undefined |
| `read(id)` | 冻结的 `{revision, challenge}`；challenge 与 get 使用同一份快照缓存 |
| `list()` | 冻结数组，元素为各题的冻结快照 |
| `findBySlug(slug)` | 匹配题目的冻结快照 |
| `state` | 冻结的整库视图，包含冻结的 challenges、order、running、stats |
| `metadata()` | 不带题目内容的冻结根元数据 |
| `addChallenge()` | 创建成功后的冻结题目快照 |

兼容 update/setStatus 返回题目时也返回当前冻结快照。flag、事实、尝试等编辑返回值继续是独立值；事务的自定义 value 是脱离存储的副本，不表示实体身份。所有这些结果都不会成为可写的内部状态别名。读取视图按 JSON 数据使用，不支持把任意运行时实例作为状态模型。

原先的 `store.get(id).status = ...`、`store.state.order.push(...)`、修改创建结果或数组元素的用法必须改为 `transact` / `transactBatch` 或兼容写方法。ESM 严格模式下，修改冻结属性或数组会抛错。取得快照后，它不会随未来写入自动更新；写后、await 后以及依赖前一步恢复结果时，应重新读取。

## 身份、内容和来源

`store.owns(snapshot)` 只判断这份题目快照是否来自本存储实例、原实体是否仍存在且存储未关闭。普通字段更新后，旧快照仍属于同一实体，但内容可能过期；删除、实体替换或关闭之后返回 false。普通对象复制、JSON 反序列化及其他状态库的同编号题目不会获得这项身份。

身份通过私有 WeakMap 关联，不写入 JSON，也不向调用方暴露内部对象。事务返回的 challenge、整库视图中的题目和创建结果均参与这项关联。它不是授权令牌，不能替代工作区权限、taskId/runId 或租约检查，也不证明内容修订仍匹配。

提交和环境服务使用 owns 检查实体，再比较目录、工作区与平台来源。流水保存仍读取最新记录，使用 expectedRevision 提交，不能因旧快照还属于同一实体就覆盖新流水。普通事实、事件和任务心跳变化不会使实体身份失效；来源或归属变化会拒绝旧操作写回。内容 revision 仍是 SHA-256，内容先变化再恢复的 ABA 边界没有变成递增版本保证。

发送前及只读查询返回后还会检查平台连接代次，避免把旧连接的排队请求发出去或用其查询结果核对当前状态。已发送的写请求继续按原凭据的流水保存已知回显，不自动重放。

## 缓存与恢复

单题快照按内部实体缓存，只有该题草稿真正安装后才失效；普通全库保存不要求复制所有未变化题目。事务已经准备好的只读结果可直接用于新缓存。整库视图按存储变更失效，并及时释放存储自身对旧整库视图的引用。调用方仍持有的旧快照保持原样。

整批事务被拒绝时不更新缓存。安装成功但保存失败时，读取会看到完整的内存修改，持久化状态仍为 dirty，后续修改继续暂停；快照存在或 owns 为 true 都不能当成写盘成功证明。

提交恢复在旧流水迁移后、流水阶段收口后重新读取；平台结果应用前也定位最新的同编号流水，避免使用旧 applied 字段反复应用。环境查询在 await 返回后读取最新环境再合并，核对数量来自写入后的记录。文件投影的旧数据迁移后也重新读取同步待办。

新任务登记核对当前资源来源及归属，拒绝从旧快照为另一资源登记。题目映射使用无原型字典并检查自有属性，不把 constructor 等继承属性误当作题目。附件加载保留平台来源及 size，避免重启后丢失刷新合并所需信息。

## 尚未覆盖

只读接口不等于 SQLite、独立读模型、增量持久化或远端停止确认。创建已有准备阶段，批量删除已有一次提交；宿主其他业务仍分多次修改，文件和网络效果不与 JSON 状态构成原子事务。缓存还会增加快照内存占用，长时间持有旧快照的调用方也需管理自身生命周期。

仅做语法及差异检查，未新增或运行测试、未修改 CI，真实宿主行为尚未验证。依赖旧可变接口的外部调用方及未来恢复测试需按新契约迁移；沙箱继续暂缓。

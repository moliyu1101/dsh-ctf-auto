# 平台题面刷新与文件恢复

`platform-refresh.js` 管理 DASCTF 题面刷新。宿主只负责工作区授权、选择题目和汇总逐题结果；`challenge-statement.js` 提供创建与刷新共用的题面 Markdown，以及刷新后的文件同步。初次平台导入仍使用原有工作流，本轮没有把创建和文件操作合成跨文件事务。

## 顺序与冲突

刷新使用平台协调器的独立串行队列，同一实例一次只暂存一组附件，其他平台操作仍使用各自的队列。队列遵守协调器现有容量和关闭规则，不持久化、不在重启后重放查询。批量刷新先授权全部请求，再在逐题排队前重新授权，并把当时的目录与工作区传给服务。排队期间归属变化会被拒绝。

服务从只读快照捕获来源、题面、附件、分类、目标、目录、状态、任务及环境记录，并捕获 statement.md 的文件身份、大小和修改时间。每次异步查询/下载结束后、附件安装前和状态提交前都重新检查；期间改题、编辑题面文件、启停任务、环境变更、切换连接或卸载实例会丢弃旧结果。连接使用包含配置代次的内部 sessionKey 判断，不把凭据摘要返回给调用方。无关的普通事实或事件变化不会直接造成整题 revision 冲突。

排队中、运行中、资源被使用/清理、任务或环境待核对、关键输入文件待同步的题目不能刷新。停止后仍需等执行端确认结束；刷新不提供强制释放资源的入口。`onlyEmpty` 保持原有默认规则：题面超过 200 字符且已有附件时跳过，可显式设为 false 刷新完整题目。

## 附件安装与状态提交

1. 查询题面并校验结构和大小；逐个下载附件到有界内存，任何下载失败都不安装本次题面和附件列表。
2. 默认最多下载 10 项，每项最多 20 MiB，总计最多 50 MiB；题面最多 2 MiB，合并后的题目附件最多 50 项。超过上限明确报错，不静默截断。
3. 已有本地和旧格式附件保留。带 `source:"platform"` 且 URL 相同的附件只更新引用；URL 不同或无法可靠识别的旧附件不猜测删除。远端没有返回附件时不清空本地列表。
4. 下载内容写入 `files/refresh-<UUID>-<序号>-<安全文件名>`，使用独占创建，不覆盖原附件或同名文件。校验目录类型，写完同步文件及目录，再让状态引用新文件。
5. 题面、合并附件、分类/目标、靶机标记、刷新事件与 `statementPending` 同步待办在同一题目事务中持久化。远端省略的靶机布尔字段保留原值，不隐式变成 false。

题面状态保存失败返回 code、applied 和持久化状态。`applied:true` 表示修改已完整安装到内存但尚未保存；不能删除新附件当作回滚，后台恢复保存后仍需要它们。安装附件后、提交状态之前失败或退出，也可能留下未被引用的新文件；暂未自动回收，避免误删仍需恢复的数据。旧文件保留会占用额外磁盘空间，强制重复刷新同样会生成新路径。

新题创建现在完整传递并保存 `hasContainer`、`requiresTarget`，修复导入时标记丢失而影响解题串行调度的问题。旧记录缺失这些标记时不猜测补全；平台刷新可按实际回显更新。

## statement.md 恢复

刷新不再忽略 `statement.md` 写入错误。`localProjection.statementPending` 与题面一起保存后，由现有投影服务写出当前状态生成的完整 Markdown，使用同目录临时文件、fsync 和 rename，成功后保存任务确认。普通文件以外的目标路径会保留并报错。投影执行前也检查存储写入所有权，已失去所有权的实例不能先改文件再尝试保存。

statement、flag 和记忆失效待办合并保留；新的 flag 操作不会覆盖尚未同步的题面意图。失败按已有退避机制恢复，也可用「重试本地同步」或 `ctf_challenge_sync` 重试。状态已保存但文件仍未同步时，刷新返回 `projectionPending:true` 和说明；这不要求重新请求平台或重新下载附件。

题面或 flag 关键输入待同步时，开始、重试、后台派发和新复核暂停；移除及记忆沉淀仍受整体投影待办保护。同步读取当前题目状态，不使用过期任务缓存的 Markdown。同步期间题目状态为权威来源，手工修改待同步的 statement.md 可能被恢复过程覆盖。

状态格式升级为 **v3**，继续读取 v1/v2，在下一次实际保存时写 v3。只支持 v2 的旧程序会拒绝加载，避免忽略 statementPending 后错误派发。回退需先停止执行端并使用匹配版本的完整备份，不应手动调低版本号。

## 范围

没有跨状态库、跨文件系统或远端事务；目录检查也不是执行沙箱，无法消除其他进程在检查后替换路径的竞态。Windows 沿用不 fsync 目录的边界。公共读取现已收敛为只读快照，初次导入的多步文件操作及未引用附件的清理仍待后续改造。

仅检查语法和差异，未新增或运行测试、未修改 CI，真实宿主和平台交互尚未验证。沙箱继续暂缓。
